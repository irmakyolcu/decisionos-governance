# Project conventions
- Public website messaging uses a dedicated shared language dictionary and existing booking routes; product visuals are sanitized captures of actual UI, while marketing claims distinguish configured source flows from simulated catalog entries.
- Shared page back navigation lives in AppLayout, skips home and detail views with existing back controls, and uses router history with a contextual direct-entry fallback to avoid duplicate controls and dead ends.
- System notifications are generated by workspace-scoped database event triggers; clients subscribe per user/workspace, and read acknowledgements use an owner-scoped RPC so auditors can acknowledge without editing business data.
- Workspace membership requires an existing workspace administrator's approval; self-service workspace/admin bootstrap is disabled, and invitation acceptance is atomic and validated server-side against the confirmed account email.
- Workspace auditor permissions use the existing membership role enum and restrictive write policies on workspace-owned tables and their child records; administrator and approver allowlists remain explicit.
- Localize interface copy through LanguageContext and its shared dictionaries; preserve stored status codes and user-authored content so language changes never modify business data.
- Format localized dates using the locale exposed by LanguageContext so displayed dates follow the selected language.
- Shared display-only translation helpers require each consuming React view to subscribe to LanguageContext; translate only rendered labels, never control values, identity props or stored data.
